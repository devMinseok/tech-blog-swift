# 시리즈 기능 설계

## 의도

이 블로그의 중심은 "뜯어보기" 시리즈다. AI가 답을 바로 주는 시대에, 그 아래에서 실제로 무슨 일이 일어나는지 직접 파보는 글들이다. 주제 하나가 방대해서 한 편으로 끝나지 않는다. 앞으로 "WWDC 신규 API"처럼 다른 시리즈도 생긴다.

독자는 시리즈 안에서 **관심 가는 주제를 골라** 읽고, 주제 안에서는 **편 순서대로** 이어 읽는다.

## 구조 (결정됨)

3단계다: **시리즈 → 주제 → 편(글)**

```
뜯어보기 (시리즈)
├── SPM 뜯어보기 (주제)  · 연재 중
│   ├── 1편
│   ├── 2편
│   └── 3편
└── iOS의 Dynamic Library (주제) · 완결
    └── 1편
```

- 시리즈는 여러 개가 될 수 있다.
- 편수는 미리 정하지 않는다. 주제마다 **연재 중 / 완결** 상태만 둔다.
- 시리즈에 속하지 않는 단독 글도 계속 존재한다. 기존 글 3개는 단독 글로 남긴다.

## 목표

- 새 시리즈·주제·편을 Markdown 파일 추가만으로 만들 수 있다. 코드를 고칠 필요가 없다.
- 시리즈 페이지에서 주제를 카드로 골라 들어간다.
- 글 페이지에서 이 글이 어느 주제의 몇 편인지 보이고, 이전 편/다음 편으로 이동할 수 있다.
- 기존 원칙을 따른다. 잘못된 콘텐츠는 빌드를 실패시키고, 모든 URL은 `SiteRoute`로 만들며, basePath가 비어 있을 때와 `/tech-blog-swift`일 때 모두 동작한다.

## 비목표

- 첫 화면(Home)은 바꾸지 않는다. 지금처럼 최신 글 위주로 둔다.
- 시리즈 전용 RSS 피드는 만들지 않는다.
- 주제에 "총 n편" 같은 예정 편수는 표시하지 않는다.
- 한 글이 여러 주제에 속하는 구조는 지원하지 않는다.

## 안티골 (이렇게 되면 실패)

- 새 주제를 추가하려고 Swift 코드를 고쳐야 한다.
- 시리즈 글이 일반 글 목록, 태그, 피드에서 빠져서 구독자가 새 편이 나온 걸 모른다.
- 오타 난 시리즈/주제 이름이 조용히 무시되어 글이 고아가 된다. 이런 경우 빌드가 실패해야 한다.

## 콘텐츠 형식

### 시리즈와 주제 정의 — `Content/Series/`

시리즈마다 디렉터리를 하나 두고, 그 안에 시리즈 파일 하나와 주제 파일들을 둔다.

```
Content/Series/
└── teardown/
    ├── _series.md        # 시리즈 정의
    ├── spm.md            # 주제 정의
    └── dynamic-library.md
```

`_series.md`:

```markdown
---
slug: teardown
title: 뜯어보기
summary: AI가 답을 주는 시대라서, 그 아래를 직접 파봅니다.
---

시리즈 소개 본문 (Markdown)
```

주제 파일 (`spm.md`):

```markdown
---
slug: spm
title: SPM 뜯어보기
summary: Package.swift부터 빌드 결과물까지
status: ongoing        # ongoing | completed, 생략하면 ongoing
---

주제 소개 본문 (Markdown)
```

- 시리즈와 주제 모두 `slug`, `title`, `summary`는 필수다.
- 새 페이지 3종의 메타 description(SEO, Open Graph)에는 각자의 summary를 쓴다. 시리즈 목록 페이지는 사이트 설명을 쓴다.
- 시리즈의 `slug`는 디렉터리 이름과 같아야 한다. 다르면 빌드가 실패한다.
- 주제 `slug`는 같은 시리즈 안에서만 유일하면 된다.
- slug 규칙은 글과 같다(`Slug.isValid`). 파싱은 기존 `FrontMatter.parse`를 재사용한다. 본문이 비면 실패하는 기존 규칙도 그대로 적용된다.

### 글 front matter 추가 필드

```markdown
series: teardown
topic: spm
part: 2
```

- 세 필드는 모두 있거나 모두 없어야 한다.
- `part`는 1 이상의 정수다.
- 순서는 날짜가 아니라 `part` 번호로 정한다. 중간 편을 끼워 넣거나 날짜를 바꿔도 순서가 흔들리지 않게 하기 위해서다.

### 빌드 시 검증 (모두 빌드 실패)

- 시리즈 디렉터리에 `_series.md`가 없음, 또는 slug가 디렉터리 이름과 다름
- 주제 slug가 같은 시리즈 안에서 중복됨
- `status` 값이 `ongoing`/`completed`가 아님
- 글의 `series`/`topic`/`part` 중 일부만 있음, `part`가 정수가 아니거나 1 미만
- 글이 존재하지 않는 시리즈나 주제를 가리킴
- 같은 (series, topic, part) 조합을 가진 글이 둘 이상 있음. 초안을 포함한 모든 파일 기준이다.
- `Content/Series` 디렉터리가 없는 것은 오류가 아니다. 시리즈가 0개일 뿐이다.

## 화면

### 상단 메뉴

"시리즈" 항목을 추가하고 `/series/`로 연결한다.

### 시리즈 목록 — `/series/`

시리즈마다 카드를 하나씩 보여준다. 카드에는 제목, summary, 주제 수가 들어간다. 보여줄 시리즈가 없으면 빈 상태 문구를 표시한다.

### 시리즈 페이지 — `/series/<series>/` (결정됨: 주제 카드형)

- 시리즈 제목, summary, 소개 본문
- 주제 카드 그리드. 카드에는 주제 제목, summary, "n편 · 연재 중/완결"이 들어가고, 누르면 주제 페이지로 간다.
- 카드에서는 편 목록을 펼치지 않는다.

### 주제 페이지 — `/series/<series>/<topic>/`

- 경로 표시 "뜯어보기 ›", 주제 제목, 연재 상태, 소개 본문
- 편 목록을 `part` 오름차순으로 보여준다. 각 항목은 "n편", 제목, 날짜, summary로 이루어지고, 글로 링크된다.

### 글 페이지 (결정됨: 가벼운 형태)

- 시리즈 글이면 제목 위에 한 줄을 표시한다: **"뜯어보기 › SPM 뜯어보기 · 2편"**. 시리즈 이름은 시리즈 페이지로, 주제 이름은 주제 페이지로 링크된다.
- 본문 아래, 댓글 위에 **이전 편 / 다음 편** 링크를 둔다. 같은 주제 안에서 공개된 글 기준으로 바로 앞뒤 편이다. 링크에는 "← n편"과 제목이 들어가고, 없는 쪽은 비워둔다.
- 단독 글은 지금과 똑같다.

### 기존 화면과의 관계

- 시리즈 글은 전체 글 목록, 태그 페이지, Atom 피드, sitemap에 일반 글처럼 나온다.
- 새 페이지 3종(시리즈 목록, 시리즈, 주제)도 sitemap에 넣는다.
- 첫 화면은 변경하지 않는다.

## 공개 범위

- 운영 빌드에서는 초안과 미래 날짜 글이 빠진다(기존 규칙). 그 결과 공개된 편이 0개인 주제는 페이지도 카드도 만들지 않는다. 보여줄 주제가 0개인 시리즈도 마찬가지다.
- 편 번호는 실제 `part` 값을 표시한다. 2편이 초안이면 운영 사이트에서는 1편 다음이 3편으로 보이며, 이는 허용한다.
- `--include-drafts` 빌드에서는 전부 보인다.

## 구현 위치 (기존 모듈 경계를 따름)

- **BlogCore**: `Series`, `Topic`(상태 포함) 모델, `BlogPost`의 선택적 시리즈 소속 정보(series/topic/part), 시리즈 로딩과 위 검증. 시리즈 로더가 주제 목록과 글을 묶어서 화면에 필요한 형태(주제별 편 목록, 이전/다음)를 계산한다.
- **BlogRouter**: `SiteRoute`에 `seriesList`, `series(String)`, `topic(series: String, topic: String)`을 추가하고, `sitePath`/`outputPath`/파서를 확장한다.
- **BlogViews**: `SeriesListView`, `SeriesView`, `TopicView`를 새로 만들고, `PostDetailView`에 위치 표시 줄과 이전/다음 편을 추가한다. 상단 메뉴도 수정한다.
- **BlogSite**: `SiteGenerator`에서 시리즈를 로드하고 새 페이지를 생성한다. sitemap도 갱신한다. 내부 링크 검증은 기존 `LinkValidator`가 그대로 처리한다.
- **스타일**: `Public/styles/site.css`에 주제 카드, 위치 표시 줄, 이전/다음 편 스타일을 추가한다. 기존 `post-card`와 다크 모드 스타일 체계를 따른다.

## 테스트

- **BlogCoreTests**: 위 검증 항목마다 실패 케이스를 하나씩 둔다. 정상 로딩, part 정렬, 이전/다음 계산, 초안 제외 시 빈 주제·빈 시리즈가 숨는지도 확인한다.
- **BlogRouterTests**: 새 라우트 3종의 path/outputPath/match를 basePath가 있을 때와 없을 때 모두 확인한다.
- **BlogSnapshotTests**: 글 페이지의 위치 표시 줄과 이전/다음 링크, 주제 카드의 "n편 · 연재 중" 렌더링을 확인한다.
- **BlogSiteTests**: 시리즈가 포함된 전체 사이트를 생성해 새 페이지 파일이 생기고 링크 검증을 통과하는지 확인한다.

## 함께 할 일

- 첫 시리즈로 `Content/Series/teardown/_series.md`(뜯어보기)를 추가한다. summary와 소개 본문은 블로그 모티브 문장("AI 딸깍으로 개발이 너무 편해져버린 나머지 원초적인 걸 파보기로 했습니다.")만 넣는다. 작성자가 나중에 다듬는다. 주제가 아직 없으므로 운영 사이트에는 보이지 않는다.
- **글과 주제는 이번 작업에서 만들지 않는다.** 작성자가 직접 조사해서 쓴다. 테스트용 시리즈/주제/글은 테스트 안의 임시 디렉터리에서만 만든다.
- `README.md`의 "글 작성" 절과 `CLAUDE.md`의 Content conventions에 시리즈 형식을 추가한다.
- `.gitignore`에 `.superpowers/`를 추가한다.

## 빌더 재량으로 둔 것 (내 판단)

- 시리즈 목록에서 시리즈의 순서, 시리즈 페이지에서 주제의 순서는 **가장 최근 편의 날짜가 최신인 순**으로 정한다. 최근에 갱신된 것이 위로 온다. 날짜가 같으면 slug 순이다.
- 시리즈/주제 정의 파일 이름은 `_series.md`로 하고, 주제 파일 이름은 자유롭게 둔다(slug는 front matter 값이 기준).
- 시리즈 목록 페이지는 시리즈가 하나뿐이어도 둔다.
- 카드, 위치 표시 줄 등의 세부 스타일은 기존 디자인을 따르는 범위에서 빌더가 정한다.
